# Controller userspace quiescence

The programmatic server lifecycle returned by `startPocketCoderServer` exposes `quiesce(signal)`. Call it from the owning operator scope, outside HTTP mutation or WebSocket frame work. Supply the same finite abort signal held by that operation.

Quiesce closes controller admission, stops the real listener and controller timers, and joins admitted HTTP work, WebSocket frames and disconnect cleanup, provider finalization, preservation and purge work. The controller keeps its store and coordinator lease open. New requests cannot launch work. A call from an admitted mutation refuses rather than waiting for itself.

The first quiesce attempt owns the result. If its signal expires, another call observes that original failed attempt. The original work still remains owned. Explicit `stop()` waits for actual original settlement before closing the store. An original controller failure refuses successful quiescence and store release. There is no automatic reopening or blind retry.

This API proves userspace controller closure only. It does not prove that every workspace process has terminated, every NFS client has flushed or unmounted, an exhaustive mount registry is fenced, or an export is continuously held. It does not implement remote operator authentication or the remote maintenance SDK. Archive capture authority must remain unavailable until those separate concrete owners and their runtime evidence are qualified.

The coordinator lease is an existing store session. A future archive database export still needs a genuine owned handoff for that session; its PID is not an exception to foreign-session refusal.

A standalone `Scheduler` owns its default operation scope. Its public `close()` closes scheduler admission and joins the complete detached finalization pipelines. Its existing `drain()` still waits only for the active tick; purge uses that narrower barrier from inside an admitted mutation. A controller supplies the shared concrete owner to its scheduler.

## Local managed-process control

The normal CLI-managed server exposes a separate literal-127.0.0.1 control listener on an ephemeral port. Run `pcd server quiesce --timeout-seconds 15` from its existing owning OS account. This command reads bounded private managed state, verifies its exact live PID and instance identity, and reads the original process-local capability through a no-follow file descriptor. The live listener authenticates that cryptographically fresh capability and checks its own PID and instance before admitting one request. The capability is not a tenant machine key and grants no remote or physical authority. It never appears in argv, URLs, logs or command output.

The control root is the existing `POCKETCODER_STATE_DIR`. It must be an owned mode-0700 real directory on a supported local filesystem, outside the current checkout and configured workspace, checkpoint, input, secret and template paths. Each instance exclusively creates a child directory and a mode-0600 capability file. Existing directories are collisions and remain untouched. Substituted identities and unknown filesystem types refuse. Linux supports local ext, tmpfs, XFS, Btrfs and overlay filesystems. macOS uses its bounded system `df -l -n` query to require the kernel's locally mounted classification.

The independent listener remains available after mutation HTTP and WebSocket closure. Its first admitted request owns the result, including expiry, failure or caller loss. Requests have at most 30 seconds, bounded bodies and exact target checks. A successful original response reports only `userspace_quiescent` and the exact PID and instance. No retry, automatic reopen or lease release follows an unknown result. `pcd server stop` retains its existing exact-process SIGTERM ownership; the controlled lifecycle settles its private listener before waiting for userspace settlement and closing the store.

Owned TCP descriptor closure precedes pathname diagnostics. Missing capability paths do not prevent listener settlement. Substituted files or directories refuse after the listener is closed and remain untouched. The owner never unlinks the private capability or removes its directory: even an unchanged identity read cannot make a later pathname deletion safe against concurrent substitution. Stopped capability files are inert and remain private for separately owned retention after process settlement. Each new managed instance uses a fresh UUID and cryptographic capability; exclusive directory creation refuses reuse or collision. Operators must retain these paths until a separate cleanup owner can prove exact deletion ownership. Unix transport was rejected because the pinned Bun implementation unlinks a substituted socket path when stopping its handle. The retained source and actual controls document that limitation; the supported TCP handle has no filesystem pathname to unlink.

Hosted use still requires genuine existing controller process/exec authority and qualified installation. The capability and local OS UID do not prove exclusive host mounts, export routes, administrator admission or physical archive completion. The foreground start path is unchanged and does not publish managed CLI state for this command.
